桌面快捷方式弹「安全警告」,真凶藏在权限的一个标签里 🕵️

📖 约 6 分钟 · #Windows #权限 #排错

桌面上双击任何一个快捷方式,都要先弹一个「你要打开此文件吗?」。 我排掉了病毒,排掉了「来自 Internet 的文件」标记, 最后发现真凶藏在一个几乎没人会点开看的地方 —— 权限里的完整性级别。 更尴尬的是:标签是我自己贴上去的。

一、症状:双击谁都要先过一道关

那天我正拿桌面当工作目录写东西。写完一抬头,桌面上的快捷方式就全变成了这样:

注意对话框里那两个字段:

  • 名称:C:\Users\18329\OneDrive\Desktop\Alas.lnk
  • 发送方:C:\Users\18329\OneDrive\Desktop\Alas.lnk

「发送方」是本地路径,和「名称」一字不差 —— 这是第一个线索: 它不像从外面下载进来的东西。 底下那句「来自 Internet 的文件可能对你有所帮助……」只是 Windows 给这一类 「来源不可信」对象的通用文案,并不代表它真的来自 Internet。

二、第一轮排除:它身上没有「来自 Internet」的标记

Windows 判断「这个文件是下载来的」,靠的是 NTFS 的备用数据流 Zone.Identifier,俗称 MOTW(Mark of the Web)。 查起来很快: 

# 看一个文件身上挂了哪些数据流
Get-Item "C:\Users\18329\OneDrive\Desktop\RevoUninstaller Pro.lnk" -Stream *

# 递归数一遍:桌面(以及全盘)有多少个 .lnk 带着 Zone.Identifier
Get-ChildItem C:\ -Recurse -Filter *.lnk -ErrorAction SilentlyContinue |
  Where-Object { Get-Item $_.FullName -Stream Zone.Identifier -ErrorAction SilentlyContinue } |
  Measure-Object

结果很干脆:

  • 桌面顶层 33 个文件,带 Zone.Identifier 的:0 个;
  • 全盘递归 *.lnk,带 MOTW 的:0 个;
  • RevoUninstaller Pro.lnk 身上只有一条 :$DATA 主数据流,干干净净。

所以 —— 不是 MOTW。可同一个警告框,还能由什么触发?

三、关键一步:去看「完整性级别」

除了「谁有权访问这个文件」(ACL),Windows 还有一层很少被提起的东西: 强制完整性控制(MIC,Mandatory Integrity Control)。 每个进程、每个对象都带一个完整性标签,由低到高是 Low → Medium → High → System。

它的规则之一是不许往上写:Medium 的进程写不了 High 的对象。 另一条规则才是这次的凶器:当一个 Medium 的进程(比如资源管理器)去启动一个 被标成 Low 的目标时,Windows 会认定它「来源不可信」, 于是弹出……跟 MOTW 一模一样的那个警告框。

用 icacls 看一眼就明白了:

icacls "C:\Users\18329\OneDrive\Desktop"

# C:\Users\18329\OneDrive\Desktop
#     ...(若干普通权限条目)...
#     Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)     <-- 就是它

Low Mandatory Level:(OI)(CI)(NW) —— 桌面整个目录被打了 低完整性标签。其中 (OI)(CI) 意味着这个标签会 继承给下面所有子目录和文件。 所以坏掉的不是某几个快捷方式,而是整个桌面五万多个对象一起变了低完整性。

两个机制,提示框长得几乎一样

MOTW(来自 Internet)低完整性级别
存在形式文件上的 Zone.Identifier 数据流安全描述符里的 Mandatory Label
谁加的浏览器 / 邮件客户端下载完成时进程主动设置(沙箱、受限运行环境)
会不会继承不继承,只跟着被下载的那个文件会,(OI)(CI) 一路传给整棵目录树
弹的框「打开文件 - 安全警告」「打开文件 - 安全警告」
怎么清右键「解除锁定」,或删掉 Zone.Identifiericacls … /setintegritylevel

同一个提示文案对应两套完全不同的机制 —— 这就是这次绕圈子的原因。

四、标签是谁贴的?—— 是我

贴标签的不是病毒,也不是 Windows 更新,是我:那个帮我干活的命令行助手(DSH)。 它为了让被降权的沙箱子进程能写进「会话工作区」,会给工作区根目录加一个 可继承的低完整性标签;凡是工作区里的东西,统统跟着变成 Low。

而那天那个会话的工作区,正好是桌面。

它自己的实现文档里把副作用写得很直白:

“A standing Low label outlives DSH and widens the tree for other Low-integrity processes.”

——一个常驻的低完整性标签会比 DSH 本身活得更久,还会把整棵目录树一起染上。它会一直待在那儿,直到有人显式把它改回来。

也就是说,这不是「文件被污染了」,而是目录的权限标签被贴错了地方: 一个本该只属于临时工作区的标签,盖到了一整个用户桌面上。

五、修复:一行 icacls

把标签改回 Medium(= 普通用户对象该有的级别),并让改动递归下去:

icacls "C:\Users\18329\OneDrive\Desktop" /setintegritylevel (OI)(CI)M /T

# Successfully processed 53073 files; Failed processing 0 files

顺手把另一个中招的工作区目录也修了(IdeaProjects,340 个对象),然后复查:

icacls "C:\Users\18329\OneDrive\Desktop"

# Mandatory Label\Medium Mandatory Level:(OI)(CI)(NW)   <-- 修好了

双击快捷方式,警告框不再出现。四个坑记一下:

  1. (OI)(CI)M 在 PowerShell 里必须加引号, 否则会被当成语法而不是参数;
  2. /T 会递归整棵子树。五万个对象要跑几十秒 —— 那不是卡死,是它在干活;
  3. 改完整性标签是提升操作,普通权限下会直接 Access is denied, 必须用管理员身份执行;
  4. 只改根目录不够,一定带上 /T;改完再查一次确认标签已经变成 Medium。

六、给以后的自己:四条经验

  1. 看到这个警告框,先别怀疑病毒。 按顺序看两个地方:文件的 Zone.Identifier,和目录的完整性级别。 两分钟就能定性。
  2. MOTW 和低完整性是两个机制,弹的却是同一个框。 只查其中一个,就会像这次一样绕远路。
  3. 别拿桌面、文档这类重要目录当工具的工作区。 给这类工具单独开一个目录(比如 D:\dsh-work), 要打标签就打它,别脏了真正在用的地方。
  4. 完整性标签是持久的,而且会继承。 想确认有没有中招,查根目录就够了 —— 只要根目录是 Low,整棵树基本都跑不掉 (除非某层被单独改过)。

七、尾声

这次真正有问题的不是任何文件,而是一个贴错位置的标签; 而贴标签的人恰恰是我。

所以结尾想写一句给自己的规矩:桌面是给人用的,不是给沙箱用的。 下次开工之前,先把工作区放到它该在的地方。

— 完 —
